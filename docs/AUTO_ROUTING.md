# エージェントの振り分け設定

入力欄の **エージェント** からエージェントを追加し、名前・モデル・Reasoning を設定します。その後、難易度判定、難易度1〜5、計画、レビュー、代替実行へ任意のエージェントを割り当てます。同じエージェントを複数の用途で使うこともできます。設定はこの端末のアプリに保存され、次の Auto 判定から反映されます。

| 難易度 | 目安 |
|---|---|
| 1 · ごく簡単 | 誤字・文言・明確な置換 |
| 2 · 簡単 | 局所的な修正、手順が明確 |
| 3 · 標準 | 複数ファイルの調査・変更・テスト |
| 4 · 難しい | 原因不明の不具合、設計判断 |
| 5 · 非常に難しい | 大きな設計変更、複雑な依存関係 |

## 設定できること

- **エージェント一覧**：1〜50件のエージェントを自由に追加・削除できます。各エージェントには1〜80文字の名前と、利用可能なモデル／Reasoningを設定します。
- **用途への割り当て**：難易度判定、難易度1〜5、計画、レビューにエージェントを選択します。判定のためのエージェントは、実行担当とは別に1回呼びます。
- **計画／レビュー**：別々のエージェントを選べます。レビューは実装 worker とは別セッションのままです。
- **判定できない・モデルが利用できない場合**：「停止して自分で選ぶ」または「別のエージェントで続ける」を選べます。
- **実行前の確認**：有効にすると、解決したエージェント名・推定難易度・モデル・Reasoning・理由を表示します。難易度を変更すると、その難易度に割り当てたエージェントのモデルへ切り替わります。

初期エージェントは Router、Quick、Builder、Developer、Engineer、Architect、Planner、Reviewer、Fallback です。初期モデルは、Router と Quick が現在のローカルモデル、その他が接続先の既定クラウドモデルです。クラウドの既定値を取得できない場合はローカルを表示します。代替実行は停止、実行前の確認はオフです。性能比較に基づく最適値ではないため、利用するモデルに合わせて調整してください。

手動でモデルを選択した依頼では難易度別の割り当てを使いません。Auto または Manifest 実行では、解決したエージェント名とモデルをタスク開始時に固定します。worker の context capsule、進捗表示、実行経路にエージェント名を残し、途中の設定変更で過去の表示を上書きしません。

## 判定と実行の境界

難易度は依頼文と指定したファイル名からの推定です。判定前にリポジトリ全体を調査するわけではありません。情報不足、応答形式不正、確度0.75未満の場合は未判定として扱います。

モデルによる判定を実行した場合は、同じ入力を後から照合できる SHA-256、依頼文・指定ファイル、判定モデルと Reasoning、ローカルモデルの量子化ビット数、判定出力、検証成否・エラー、記録時刻を既存の SQLite に保存します。履歴は `difficulty_history:<project_id>` という内部設定に JSON で直近50件だけ保持します。手動で難易度を変更しても、元のモデル判定は上書きしません。

難易度と操作のリスクは別です。設計・認証・移行など計画が必要な依頼は「計画する」へ案内し、難易度を下げてもその条件は解除しません。ローカル編集は低リスク、指定ファイル1〜2件、推定100行未満という既存の範囲を維持します。判定が不確かな場合、代替先をローカルにしてもこの条件は満たせません。

代替モデルを使うのは判定・実行先の確認段階だけです。実行開始後に失敗した作業を別モデルで自動再実行しません。判定モデルをクラウドにした場合は、依頼文とファイル名をそのモデルへ送信します。判定にも選択先の利用枠を使います。

確認画面での変更は再判定を行わず、保存済みの判定から実行先を更新します。実行時には依頼・対象ファイル・プロジェクト・設定の版を再照合し、一度使った判定や10分以上経過した判定は受け付けません。

## 確認したこと

- エージェント設定対応では、`hub-router` 8件、自動振り分け 5件、画面側 75件のテストとデスクトップの型チェック・production buildが成功しました。旧設定からの移行、追加・削除と再割り当て、計画・レビュー担当の解決、worker capsuleと進捗表示を含みます。
- UI監査では、エージェント設定のライト／ダーク表示と375px幅で、アクセシビリティ違反、横あふれ、小さなタップ領域がいずれも0件でした。
- Codex の実モデル一覧から Reasoning の選択肢を表示。モデル／effort の送信と再開後の保持は通信fixtureで検証しました。
- macOS アプリと Spark X-2.5 8bit の実接続で、誤字修正を難易度1と判定。確認画面で2へ変更するとクラウドの割り当てへ切り替わり、1へ戻して実行すると期待どおりのローカル編集が完了しました。実行前はファイル未変更でした。
- クラウド全モデルでの実タスク、Reasoning ごとの速度・品質比較は行っていません。

モデルの差し替えや個別選択は [モデル設定](MODEL_CONFIGURATION.md) を参照してください。
