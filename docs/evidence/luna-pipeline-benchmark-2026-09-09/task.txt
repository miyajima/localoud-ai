# Astra implementation plan: dependency scheduler

Goal: implement the exact scheduler contract in policy.md with Python standard library only. Deliver scheduler.py and test_scheduler.py; preserve every supplied file. No delegation or network access.

1. Read policy.md, AGENTS.md and acceptance.py together. Keep topological choice, execution batches and critical path as separate operations because their readiness semantics differ.
2. Build one private validation helper. Require a dict with nonempty string IDs and exact field keys deps/duration/group. Validate field types before membership checks so malformed or unhashable dependencies become ValueError. Duration and capacity must be positive integers excluding bool; group must be None or a nonempty string; deps must be a list of nonempty strings referring to known IDs. Copy dependencies into sets to deduplicate without mutating callers. Reject self-dependencies. Validate all nodes, including disconnected components, before returning any result.
3. Derive a lexicographically minimal topological order with Kahn's algorithm and a min-heap of currently ready IDs. Decrement successors after each individual pop and push newly ready IDs immediately. If fewer nodes are emitted than exist, raise ValueError for the cycle. Reuse validated graph/order internally where useful; avoid global mutable state.
4. For execution_batches, validate max_parallel even for an empty graph. Maintain completed and pending sets. At each batch boundary gather IDs whose dependencies are all completed, sort, then scan once: skip a conflicting non-None group, append compatible IDs until capacity is reached. Do not mark selected tasks completed until the batch is finalized. None groups do not conflict. Keep returned batches deterministic and return [] for no tasks.
5. For critical_path_length, walk the validated topological order. The longest finish value for each node is its duration plus the maximum finish value of its dependencies, with zero for an empty predecessor set. Return the maximum finish value, or 0 for an empty graph. Group constraints do not enter this calculation.
6. Add focused tests for newly ready lexicographic priority, delayed readiness between batches, skipping group conflicts to fill capacity, duplicate dependencies, disconnected cycles, malformed schemas, bool rejection, immutability, and weighted critical paths. Include small deterministic generated DAGs if useful. Run python3 -B -m unittest -v test_scheduler acceptance. Fix failures within the two-file scope and report final results concisely.

Acceptance: all 12 supplied tests plus worker tests pass; only scheduler.py and test_scheduler.py change; results match the stated greedy and dependency semantics. Do not add extra APIs, dependencies, CLI features, or unrelated refactoring.
