# Astraで計画してから実装する1エージェント比較

後続の [Astra/low → Luna/max → Astra/low 比較](LUNA_PIPELINE_BENCHMARK.md) では実装モデルとnative履歴設定を変更し、両成果物へのレビューまで測定した。以下とは条件を分けて参照する。

2026-09-09 JST。Codex内の親Astraで計画を確定し、同じ計画を実際のCodex native subagent 1体とLocaloudの独立worker 1体へ渡した。この1ペアではLocaloudの実装入力が71.0%多く、計画を渡した構成でもトークン節約は確認できなかった。

## 構成と固定条件

- 計画: 現在のCodex親タスク、`gpt-6-astra` / `low`。
- Codex実装: 実際の `spawn_agent`、`fork_turns=all`、親モデルを継承。追加子・追加指示・再実行なし。
- Localoud実装: `CodexProvider::start_worker` による独立 `thread/start` と `start_turn_in_worktree`。計画を本文として渡した。追加worker・再実行なし。
- 両実装とも実行ログで `gpt-6-astra` / `low` を確認。計画は [PLAN.md](evidence/planned-agent-benchmark-2026-09-09/PLAN.md) の1つを共用し、両worker開始前のハッシュを固定した。
- 新しい依存関係スケジューラ課題で、実行順序・同時実行バッチ・最長依存経路を実装。同じGitコミット、方針、固定テストから別の作業ディレクトリを作成した。前回の区間処理の実装を再利用していない。

計画は入力検証、アルゴリズム、バッチの準備完了条件、グループ競合の扱い、テスト方針、編集範囲まで指定した。実装済みのコードは渡していない。

## 実装workerの実測

| 指標 | Codex native subagent | Localoud worker |
|---|---:|---:|
| 初回入力 | 36,933 | 26,308 |
| 累計入力（キャッシュを含む） | 116,929 | 199,972 |
| うちキャッシュ済み入力 | 109,440 | 135,168 |
| キャッシュを除く入力 | 7,489 | 64,804 |
| 出力 | 2,555 | 3,255 |
| 入力＋出力 | 119,484 | 203,227 |
| モデル呼び出し回数 | 3 | 6 |
| 実行時間（概数） | 94.5秒 | 122.0秒 |
| 固定テスト | 12/12 | 12/12 |
| 各workerの追加テスト | 6/6 | 8/8 |
| 実行後の共通生成DAG検証 | 1,000/1,000 | 1,000/1,000 |

Localoudの初回入力は28.8%少ないが、累計入力は71.0%多く、入力＋出力は70.1%多い。キャッシュを除く入力は約8.65倍だった。Localoud側では追加の指示ファイル取得、実装前のファイルハッシュ収集、実装後の範囲・ハッシュ確認が別の推論を挟んで行われた。モデルの確率的な行動とキャッシュ状態が異なるため、これらの差をLocaloudの構造だけの必然的な結果とは断定しない。

共通の追加検証はseed固定の1,000個のDAG（最大6ノード）を使用。全順列から正しいトポロジカル順を選び、実行可能な部分集合を列挙して各バッチを照合し、依存経路を列挙して最長経路を照合した。並列数1・2・3・7と入力不変性も確認した。両workerとも変更は指定した2ファイルのみで、計画・方針・固定テストは不変だった。

## 共通計画分を加えた参考値

親Astraが計画を生成・保存した1推論は、入力95,650（うちキャッシュ93,312、非キャッシュ2,338）、出力1,499、合計97,149トークンだった。計画本文だけでなく、同じ推論で出力した保存・fixture準備用ツール呼び出しも含む。前後の調査・課題準備・計測・レビュー・集計は含まない。

計画は実際には1回だけ生成して共有した。以下は「その共通計画1回＋各実装worker」の組み合わせであり、計画を別々に2回実行した数値ではない。

## 証拠と解釈の限界

集計は [report.json](evidence/planned-agent-benchmark-2026-09-09/report.json)、計画生成の推論は [planner-usage.json](evidence/planned-agent-benchmark-2026-09-09/planner-usage.json)、実装usageは [Codex](evidence/planned-agent-benchmark-2026-09-09/native/usage.json) と [Localoud](evidence/planned-agent-benchmark-2026-09-09/localoud/usage.json)。同じディレクトリに両実装・検証出力・共通oracleを保持している。各子のusage増分合計と最終累計が一致することを確認した。親の累積使用量やキャッシュ内数を重複加算していない。

1課題・1ペアであり、一般的な削減率ではない。native側は利用可能な親履歴を引き継ぐが、圧縮前の全会話ではない。システム指示・ツール一覧・履歴・キャッシュ状態は両者で異なる。Localoud本体のworker起動経路は使用しているが、UIのManifest取り込みやChatGPTの計画・レビューを含む全工程の計測ではない。プラットフォーム内部のguardianも集計対象外で、サブスクリプション消費量とは結びつけない。課題と親コンテキストが前回とは異なるので、前回との差を「計画追加による改善・悪化」とは評価できない。
