# 同じセッションでプラン・実装・レビュー

入力欄の **プラン → 実装 → レビュー** から操作を切り替えます。利用先は隣に **ChatGPT / Codex** と表示します。通常実行・Codexでの相談・ゴール・分割実行計画は **＋ → 追加の操作** にまとめています。操作を選んだ時点では送信しません。モデル・Reasoningを確認して、入力欄から送信してください。

- **プラン**: ChatGPTまたはCodexのモデルを選択できます。Codexは変更を行わないPlanモードで相談します。
- **実装**: 要件・プラン・直近のレビューをCodexに引き継ぎます。追加指示がなければ入力欄が空でも送信できます。
- **レビュー**: 会話・実装結果・作業差分を、選んだChatGPTまたはCodexに渡します。CodexはPlanモードでレビューし、修正は実装段階で行います。追加の観点がなければ入力欄が空でも送信できます。
- レビュー後、**実装**へ戻ると指摘を引き継いで修正できます。

サイドバーには1つのセッションを表示し、会話には各段階とモデルを表示します。内部のChatGPT会話とCodex会話は別々に保持し、同じ会話を継続利用します。各段階で明示的に選んだモデル・Reasoningを使います。同じモデルIDでもChatGPTとCodexは別経路です。ChatGPTの利用枠がなくなっても、手動でCodexを選んで続行できます。失敗時の自動切り替えは行いません。同名でも内部モデルIDが異なる候補にはIDを併記し、Reasoningの選択肢もモデルごとに表示します。

既存のCodexセッションも **レビュー** から引き継げます。既存の会話と作業フォルダを保持します。実行中は段階を切り替えられず、停止ボタンは実行中の側へ送られます。再起動後は保存したセッション・段階・下書き・モデルを復元し、**再開・状態を確認**でプロバイダーの状態を再取得します。

## ChatGPTの初回接続

1. **接続設定 → ChatGPTを接続する**を開きます。
2. Chromeの拡張機能管理画面でデベロッパーモードを有効にし、「パッケージ化されていない拡張機能を読み込む」で、アプリに表示された `extensions/chatgpt` フォルダを選びます。
3. アプリで接続キーをコピーし、拡張のポップアップに貼り付けます。
4. そのChromeプロファイルでChatGPTにログインし、拡張の **このChatGPTタブのモデルを確認** を押します。
5. アプリで **接続を更新** を押し、ChatGPT欄に表示されたAstra等のモデルを選びます。

拡張機能のインストールとログインは手動です。この環境のブラウザー操作ツールでは拡張機能管理画面を操作できません。拡張を読み込んだプロジェクトフォルダは移動しないでください。

接続キーはローカルのChrome拡張を認証するもので、OpenAI APIキーではありません。ブラウザー連携は認証済みのループバック接続のみを使います。MCPサーバー・トンネル・MCP編集要求のUIは削除しました。MCPアプリの追加設定は不要です。

## 自動で渡す資料

会話内の **自動で引き継いだ内容** を開くと、送った引き継ぎ資料を確認できます。

- 要件と各段階の応答。長い会話では最初の依頼と直近の応答を優先し、上限で省略した箇所を明記します。
- ワークフロー内で実装を始めた場合は、その時点のHEADから現在の作業ツリーまでの差分。実装中のコミット・ステージ済み・未ステージの変更を含みます。開始前から未コミットの変更があった場合は、その旨も伝えます。
- Gitで無視されていない新規ファイルの本文。最大40件、1件20KBまで。シンボリックリンク・バイナリ・機密候補のパスは読みません。
- 機密候補の追跡済みファイルの差分は除外し、既存の秘匿化ルールも適用します。大きな差分やファイルは省略・取得失敗として明示します。

既存の通常Codexセッションからレビューだけを始める場合は、保存済みのworker基準差分、または現在のHEADに対する作業差分を使います。開始コミットが保存されていない通常セッションについて、過去にコミット済みの変更をすべて含む保証はありません。この範囲はレビュー資料に明記します。新しく実装を始めるリポジトリには初期コミットが必要です。

ChatGPTは添付資料をもとにレビューします。任意の追加ファイルを直接読んだり、ローカルでコマンドを実行したりする機能はありません。実装結果に含まれるテスト報告はCodexの報告として渡し、ChatGPT自身がテストを実行・検証したとは扱いません。追加調査が必要なら同じセッションの実装段階へ戻って依頼します。

## セッションの管理

セッションの **⋯** から名前変更・アーカイブ・復元・履歴削除ができます。連携した内部セッションもまとめて対象にします。実行中の内部セッションがあれば操作を拒否します。削除はアプリ内の会話・引き継ぎ資料・対応付けが対象で、プロバイダー側の会話や作業ファイルは残します。プロジェクトの登録解除もファイルを削除しません。

## 検証の範囲

Rustのローカルfixtureで履歴・対応付けの復元、進行中の保護、差分と新規ファイルの収集、機密候補・外部リンク先の除外を検証します。画面fixtureでは同じセッションIDでの3段階操作、モデル経路、再開・停止、失敗時の下書き保持と非フォールバックを検証します。

実アカウントでのChatGPT/Astra応答と3段階の完走、利用枠の増減は、拡張導入・ログイン後の確認が必要です。別のコード経路であることだけを利用枠の実測証拠とは扱いません。
