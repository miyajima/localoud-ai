# Codex Desktop との UX 比較と採用結果

確認日: 2026-09-08。比較対象は改善前の Astra Hub (`bf47bf9`) と、OpenAI が公開する現在のデスクトップ仕様です。Codex Desktop 自体はこの環境の Computer Use 制限で操作できないため、実機の全画面を比較したとは扱いません。フォルダ選択の不足はユーザーからの指摘でも確認しています。

根拠: [操作・ショートカット](https://learn.chatgpt.com/docs/reference/commands)、[プロジェクト・チャットの整理](https://learn.chatgpt.com/docs/projects)、[レビュー画面](https://learn.chatgpt.com/docs/code-review)。下表の「Hub 監査」は Codex の挙動を断定する項目ではなく、Hub の操作・コードから見つけた改善です。

## 実装上の範囲

- フォルダ・ファイル選択は [Tauri のネイティブ Dialog](https://v2.tauri.app/plugin/dialog/) を専用 Rust コマンドから呼び出す。汎用のファイル読み書き権限はフロントエンドに追加しない。
- 下書き・選択状態・固定・計画編集中の JSON は、このアプリの端末内 WebView storage に保存する。同期はしない。接続資格情報は従来どおり Keychain。
- Markdown は DOMPurify で許可した要素・属性だけを表示。外部リンクのスキームは Rust 側でも HTTP(S) に制限する。
- 変更前のモデルトークン計測、ワーカー実装、承認境界を変えない。

## 検証

- ネイティブ UI: フォルダ選択・キャンセル・locloud 登録、⌘K 検索から既存 fixture タスクへ移動、名前変更・固定、Markdown・差分表示、⌘, と実行ファイル選択のキャンセル、⌘B を確認。
- プロジェクトを切り替えて下書きが復元されることを確認。送信ボタンは押していない。
- Markdown の HTML 注入・危険リンク・リモート画像、diff のヘッダーを除いた行数、壊れた計画 JSON を4テストで確認。
- DB の名前変更がプロバイダーの状態更新で消えないこと、空欄の拒否を既存テストに追加して確認。
- TypeScript/Vite、Rust clippy、macOS bundle のビルドを確認。最新の微調整後にも再起動し、選択プロジェクト・タブ・下書き・固定・変更した名前の復元を確認。Plan が先頭から表示され、未編集テンプレートの実行ボタンが無効であることも確認した。検証用の下書き・固定・名前変更は元に戻した。

- 最終確認では新規のモデル推論・実コード変更を依頼していない。既存 fixture の会話を再開して表示し、登録・表示・整理操作を検証した。
